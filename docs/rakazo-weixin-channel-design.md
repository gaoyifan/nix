# Rakazo 个人微信聊天接入方案

为用户通过个人微信与 AI 助手私聊提供接入。每位用户扫码建立自己的微信连接，选择一个 Rakazo Bot 处理消息；所有连接共用一套微信接入服务。本方案尚未实现。

## 用户流程

1. 用户登录 Rakazo，在 Messaging 中选择添加微信，并选择接收消息的 Bot。
2. 页面显示二维码，用户用微信扫码并确认授权。
3. 服务端将授权结果关联到当前登录用户，页面显示连接状态和所选 Bot。
4. 用户在微信向助手发消息，回复返回同一微信会话，聊天同步到所选 Bot 的 Rakazo 会话。

用户可在网页切换处理消息的 Bot，无需重新扫码。重新授权也不改变已有 Bot 的聊天历史。

## 身份绑定与消息路由

| 对象 | 职责 |
| --- | --- |
| 微信连接 | 保存授权凭据、微信 Bot 身份和授权用户身份，负责消息收发 |
| Rakazo 用户 | 拥有微信连接，只能绑定自己有权使用的 Bot |
| Rakazo Bot | 处理消息，维护自己的聊天和记忆 |

路由关系为：

```text
微信连接 + 发送者身份 → Rakazo 用户 → 该连接选定的 Bot → Bot 的聊天会话
```

扫码请求须关联当前登录用户；授权完成后，以微信返回的用户身份校验后续消息发送者。昵称不作为身份依据。微信返回的 Bot 身份、扫码用户身份和凭据可用于完成绑定，用户无需额外发送绑定码。[腾讯扫码协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md#二维码登录)

第一版每个连接只选择一个 Bot。收到消息时固定本次处理使用的 Bot 和回复目标；处理中切换绑定，只影响后续消息。切换 Bot 不复制其他 Bot 的历史。

## 连接管理

统一的微信接入服务管理多位用户的连接，按连接分别保存加密凭据、收消息游标和回复所需的会话上下文。用户和 Bot 的权限由 Rakazo 校验，回复由收发层直接投递。

多位用户共享服务进程和部署，每位用户保留独立的微信授权与绑定关系。无需为每人运行一套应用，也不预设所有人共用同一个微信 Bot 身份。[腾讯多账号说明](https://github.com/Tencent/openclaw-weixin/blob/main/README.zh_CN.md#多账号)

连接失效时暂停该连接并提示重新扫码；解除连接时停止收发并删除本地凭据，保留 Bot 的聊天历史。

首版范围为扫码连接、私聊收发、Bot 选择与切换、连接状态和重新授权。群聊、自动选择 Bot 和多个 Bot 同时回复留待有明确需求时再设计。
