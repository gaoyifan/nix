# Find My history

Hackintosh sends snapshots over SSE; this TypeScript service stores distinct fixes in SQLite and serves a private MapLibre dashboard. Application source and reusable Nix modules live in [gaoyifan/findmy-history](https://github.com/gaoyifan/findmy-history). This repository only configures the hosts, encrypted storage, HTTP source authentication and private ingress.

For application setup, APIs and development, see the [upstream documentation](https://github.com/gaoyifan/findmy-history#readme).

## Nix integration

`flake.nix` pins `findmy-history` in `flake.lock`, with its Nixpkgs input following the host input. The upstream project supplies `packages.<system>.dashboard`, `nixosModules.default` and `homeManagerModules.source`. The source module builds against the host's Darwin packages so its Python environment follows that host's lock.

`home-manager/hackintosh.nix` enables the upstream source module. `nixos/hosts/el2/services/findmy.nix` enables the recorder module and adds mount ordering, the source token path and Tailscale ingress. Update application code in the independent repository, then update only this input with `nix flake update findmy-history` and review the lock diff before deploying.

## Deployed service

The private dashboard is **https://findmy.ts.gaof.net** (Tailscale required). The Mac source listens on its VM-private address `100.64.2.80:8766`; the el2 recorder connects directly to `http://100.64.2.80:8766/events` using `Authorization: Bearer <token>`. Both `/events` and `/healthz` require that header. Missing or incorrect credentials receive HTTP 401. The dashboard still listens on el2's `127.0.0.1:8787` behind the existing private ingress. Decryption keys never leave the guest.

The shared source token is a private runtime file, `~/.local/state/findmy/source.token` on the Mac and `/pool1/services/findmy/source.token` on el2, mode `0600`. The latter is owned by `findmy` on the encrypted services dataset. The token is separate from the cache decryption keys and is not stored in Git or the Nix store. Restart both services after replacing the token.

- macOS: `home-manager/hackintosh.nix` installs `org.nix-community.home.findmy-source`. It starts in the logged-in Aqua session and restarts the reader when it exits. The supervisor renews Find My's background session every four minutes by terminating only this user's Find My app, waiting for exit and reopening it without activation. A continuously running background app stops refreshing after five minutes on this macOS build; `open -g` on the existing process does not recover it. The VM is left on Items. The reader and Apple's agents stay running across renewals. The supervisor opens a worker in Terminal, which already has Full Disk Access on this VM. macOS Automation also needs to allow this Python interpreter to control Terminal. A different interpreter identity after an upgrade may require approving this again. Logging out stops collection; this VM has automatic login enabled.
- Reader: the upstream `macos/source.py` samples every 30 seconds. It briefly pauses `findmylocateagent` while copying the encrypted database and WAL into memory, resumes it in `finally`, validates WAL checksums, and applies only committed transactions. It decrypts/query-checks SQLite in memory and verifies the authenticated device cache envelope. It never writes to Apple's cache or accumulates plaintext database snapshots.
- Runtime secrets: `~/.local/state/findmy/keys/LocalStorage.key` (32 raw bytes) and `FMIPDataManager.bplist`, directory mode 0700 and files 0600. These are the keys extracted during validation; normal collection runs with SIP enabled and the configured virtual Bluetooth transport. Do not put these files in Git or a Nix expression. See [the validation report](research/find-my-location-cli.md) for extraction provenance and limitations.
- el2: `findmy.service` reconnects authenticated SSE, stores `/pool1/services/findmy/findmy.sqlite`, and serves the UI. It restarts automatically. The recorder waits for the encrypted dataset to unlock. The directory is 0700 and SQLite files are 0600, owned by `findmy`. Existing `pool1/services` ZFS snapshots include the database and WAL together.

Cache sampling does not force Apple to obtain a new location. Cache refresh depends on Find My app state; keep it open in the background. The UI distinguishes the last received snapshot from each object's source location time. People, devices and items are readable. Item records use `identifier`, whereas device records use `id`; both carry millisecond Unix source times in `location.timeStamp`. Items include AirTags and individual audio accessory components, so their count is not an AirTag count. When a cache changes to an unsupported format or a key no longer matches, its error is shown while saved history remains accessible.

The previous OpenCore patch that forced `IOBluetoothHCIController::start` to return false must remain disabled. On this macOS build it leaves `bluetoothd` waiting for the removed controller and blocks `searchpartyuseragent` in `CBPairingAgent` initialization; the Items tab stays at Loading and no `Items.data` is generated. This VM instead uses `bt-transport-override=10` with the HCI controller present, selecting macOS's built-in virtual Bluetooth transport without a physical adapter. This private boot argument was verified against this macOS build and needs revalidation after an OS upgrade. See [the CPU investigation follow-up](research/hackintosh-idle-cpu.md) for the guest configuration and its verification.

The Tailscale Service `svc:findmy` has endpoint `tcp:443` and el2 is approved as its host. The existing DNS syncer publishes its private address in `ts.gaof.net`. If recreating the Service, defining it and approving its host are separate steps; the Nix Serve configuration alone does not create the control-plane Service.
